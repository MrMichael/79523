## 1. 技术栈

| 层 | 技术 | 理由 |
|---|---|---|
| 前端 | Vue 3 + Vite + Pinia | SFC 直观，Composition API 灵活，Vite 热更新快 |
| 通信 | Socket.io | 自动处理重连、房间、广播，比裸 WebSocket 省代码 |
| 后端 | Node.js + Express + Socket.io | 一种语言两端复用类型 |
| 游戏状态 | 进程内存 | 原型阶段一台机器足够，后续加 Redis 成本低 |

不做：NestJS（太重）、Go（两套语言）、Redis/数据库（先跑通核心玩法）

## 3. 游戏规则（engine 层定义）

### 牌序

```
7 > 9 > 5 > 2 > 3 > A > K > Q > J > 10 > 8 > 6 > 4
```

花色：♠ > ♥ > ♣ > ♦

### 牌型（5 种）

| 牌型 | 英文 | 组成 | 张数 | 比大小规则 |
|------|------|------|------|-----------|
| 单张 | Single | 单独一张 | 1 | 比牌点，同点比花色 |
| 对子 | Pair | 两张相同 | 2 | 比对子牌点 |
| 单车 | Bike | 对子 + 任意单张 | 3 | 比对子牌点 |
| 三条 | Triple | 三张相同 | 3 | 比三条牌点 |
| 根号 | Root | 两对 + 任意单张 | 5 | 比最大的对子 |

**牌型隔离：** 必须跟牌型，不同牌型之间不能互压。

### 计分

- 5 = 5 分
- 10 = 10 分
- K = 10 分
- 其他牌不计分

### 牌数

- < 4 人：1 副牌（52 张，无鬼牌）
- 4-6 人：2 副牌（104 张，无鬼牌）

## 4. 游戏流程

### 一局

1. **发牌：** 每人 5 张
2. **首出：** 持有最小单张牌的玩家先出
3. **循环：** 出牌 → 判定 → 补牌 → 下家
4. **结束：** 牌堆抽干 + 有人出完手牌
5. **结算：** 拳王分配剩余计分牌 → 统计当局得分 → 上缴换牌 → 下一局

### 一墩

1. 当前玩家出牌（符合牌型的组合）
2. 下家跟牌（同牌型且更大）或过
3. 除一人外全过 → 该人赢下此墩
4. 赢家收走桌上的计分牌（5/10/K）
5. 参与者补牌至 5 张

### 上缴+换牌（整局结束后）

1. 当局得分最高的 2 位是赢家，最低的 2 位是输家
2. 每个输家交出手中最大的单张
3. 第一赢家拿较大的牌，第二赢家拿较小的牌
4. 赢家各选 1 张单张还给对应输家
5. 交出最大牌的输家为下一局先手
6. <4 人模式：只涉及 1 输 1 赢

### 拳王

1. 一张一张分配未出计分牌
2. 参与者确认出拳（石头/剪刀/布）
3. 3-2-1 倒计时后揭晓
4. 输者出局，直到一人胜出
5. 胜者获得拳王徽章 + 该计分牌

### 分数并列

拳王决定谁优先。

## 6. Engine 层

### 文件结构

```
engine/src/
├── types.ts      # Card, Suit, Rank, HandType, Play
├── deck.ts       # createDeck, shuffle (Fisher-Yates), draw
├── judge.ts      # identify (识别牌型), beats (判定大小)
├── compare.ts    # 同牌型比较 (含花色)
├── score.ts      # 计分牌识别、当局得分计算
├── boxer.ts      # 拳王猜拳逻辑
└── index.ts      # 统一导出
```

### 核心类型

```typescript
enum Suit { Spade, Heart, Club, Diamond }
enum Rank { Four=0, Six, Eight, Ten, Jack, Queen, King, Ace, Three, Two, Five, Nine, Seven }

interface Card { suit: Suit; rank: Rank }

enum HandType { Single, Pair, Bike, Triple, Root }

interface Play {
  type: HandType
  cards: Card[]
  primaryRank: Rank
}
```

### 关键函数

```typescript
// deck
createDeck(playerCount: number): Card[]
shuffle(deck: Card[]): Card[]
draw(deck: Card[], n: number): { drawn: Card[]; deck: Card[] }

// judge
identify(cards: Card[]): Play | null    // null = 不合法
beats(newPlay: Play, currentBest: Play): boolean

// score
calculate(cards: Card[]): number
needsBoxer(unplayedCards: Card[]): Card[]

// boxer
resolveRound(moves: Map<pId, Move>): pId[]
finalWinner(survivors: pId[]): pId
```

### 测试

纯函数，`npx vitest` ~80 个测试用例。deck / judge / compare / score / boxer 各一个 spec。

## 7. Server 层

### 文件结构

```
server/src/
├── index.ts         # Express + Socket.io 启动
├── api.ts           # REST: GET/POST /rooms
├── ws.ts            # Socket.io 事件分发
├── room.ts          # 房间管理
├── game-machine.ts  # 游戏状态机
├── player.ts        # 玩家状态
└── utils.ts         # 日志、校验
```

### 游戏状态机

```
WAITING → DEALING → PLAYING ⇄ ROUND_END
                           ↘ SETTLING → WAITING
```

| 状态 | 事件 | 下一状态 | 服务端动作 |
|------|------|----------|-----------|
| WAITING | 全员ready | DEALING | 创建牌堆、洗牌、发5张 |
| DEALING | 动画完成 | PLAYING | 算最小单张者，通知 your_turn |
| PLAYING | 出牌 | ROUND_END | engine.judge → broadcast play_made |
| PLAYING | 过 | PLAYING | 通知下家 |
| ROUND_END | 补牌 | PLAYING/SETTLING | engine.draw → 判定是否局结束 |
| SETTLING | 拳王+换牌 | WAITING | 分配分数 → 广播结果 |

### Socket.io 事件

**客户端→服务端：** create_room, join_room, ready, play, pass, boxer_move, leave_room, reconnect

**服务端→客户端：** room_created, player_joined, game_started, your_turn(timeout=30), play_made, round_result, draw_card, game_over, boxer_start, boxer_reveal, boxer_winner, surrender_swap, next_game_lead, player_disconnected, player_reconnected

### 测试

集成测试：~15 个用例，用 socket.io-client 模拟 4 客户端。

## 9. 错误处理

### 三层防线

1. **Engine：** 非法输入抛 `GameError({code})`
2. **Server：** try-catch 所有事件，超时 30s 自动 pass，空房 10min 销毁，断线 30s 踢出
3. **Client：** 出牌前本地预校验，断连显示重连遮罩，错误 Toast 提示

### 边界情况

| 场景 | 处理 |
|------|------|
| 牌堆抽干但无人出完 | 继续打到有人出完 |
| 断线重连后已过回合 | full_state 恢复 |
| 拳王仅剩1人 | 自动获胜 |
| <4人模式 | 上缴换牌 1v1 |
| 分数并列 | 拳王决定优先级 |

## 11. 不做的事

- 无登录/注册（昵称即可）

- 无大厅匹配（仅房间码加入）
- 无观战模式（原型阶段）
- 无表情包互动（仅快捷语）
- 无音效（原型阶段跳过）
- 无 CI/CD
- 无 Docker 部署（`npm run dev` 即可）

## 验证方式
